# Changelog

All notable changes to Turbohaul-Manager are documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

GitHub (`https://github.com/MrTrenchTrucker/turbohaul-manager`) is the canonical public repository.

## [v0.8.0] - 2026-10-05

### Highlights

- 🚦 **Fast Lane adds an optional two-level request priority scheme.** An ordered list of caller addresses -- or container names -- decides which caller is served first, and a rank per traffic class decides which request inside that caller goes next. The feature is off by default, and while it is off request ordering is exactly as it was.
- 📊 **The dashboard is now built around per-model residents (a loaded model the manager keeps in VRAM).** The live-inference panel now describes the whole machine at once, and every loaded model gets its own card carrying its own throughput, graph, prefill/output split, state badge and live output box.
- 🗂️ **Models, blobs and manifests are managed from the web UI.** The model store is browsable as a blob store: every model gets its own tile, the Blobs tab gained search and sort, and model rows show details read from the GGUF header itself. Models and manifests carry an editable description, with a model's description stored against its blob digest so it survives renaming or duplicating a manifest. A model can be hidden from the discovery listings with one control, and a per-model control restores its defaults. The blob store is also enumerable through the API (`GET /api/blobs`) for the first time.
- 🚛 **One model can now run several engines.** A single model tag can run one engine per GPU, with each session pinned to the engine already holding its cached context and any overflow queued rather than rejected. The host-wide `queue.max_parallel_sidecars` budget decides how many engines run (a second engine of one model needs `auto_place: true` and `llama_server_flags.split_mode: none`), replacing the per-model `max_instances` key.
- ♻️ **A long-running conversation keeps its warm cache across reloads and hand-offs.** An engine that reloads still restores its precomputed KV cache rather than re-prefilling the prompt from cold, while a short-lived request that borrows the same engine no longer costs the resident conversation its saved state, and the save-side gate now keys off observed concurrency rather than the configured cap, so a box with idle siblings no longer silently loses its clean prefix.
- ⚡ **Speculative decoding is per-model and multi-type.** D-Flash and D-Spark join MTP as first-class drafter types, each configurable from the manifest editor, with a named error instead of an engine crash if more than one model-based drafter is configured.
- 🔌 **A manifest can now describe a plugin as well as a model.** A plugin is registered alongside the models with its own lane, capabilities and resource key, and is invoked either over HTTP or through a transparent WebSocket exec that runs an allow-listed binary. A boot-only registry maps each resource key to a container, so no manifest ever carries a URL or a filesystem path. The Plugins surface ships as work in progress, and feedback and contributions are welcome.
- 🔭 **Model discovery reports the context window.** The OpenAI-compatible model endpoints now carry each model's resolved context length and say where that number came from, so a client no longer has to guess.
- ⚠️ **One retired setting will stop the manager from starting until the configuration file is edited.** A configuration file that still carries the old queue safety ceiling is rejected as a validation error, so an upgrade can need an edit before the manager will boot; see the Compatibility section for which setting and what to change it to.


### Added

**Fast Lane**

- ✨ Fast Lane, an optional two-level request priority scheme that decides which waiting request gets the GPU next: an ordered list of caller addresses, or of container names resolved by forward lookup, plus a rank from 1 to 5 per traffic class (`main`, `curator`, `compression`, `sub_agent`, `unclassified`) within each address. It is off by default, and while off request ordering is exactly as it was. A configuration may name at most 10 clients, because the list index is the priority and there is no room for a client outside that range to be ranked meaningfully: an eleventh is refused when the configuration is saved, and an over-long list carried in a file is trimmed with a warning at startup.
- ✨ With Fast Lane on, requests waiting for the same model are ordered by priority at admission rather than strictly first-come-first-served, a listed waiter is protected from eviction by its rank rather than by being listed, a requeued request keeps its place in line, and an unlisted request that has waited past the configurable fairness floor is promoted regardless of priority -- the floor does not rescue a listed address, which is governed by the lane and its eviction cooldown, so re-rank it instead.
- ✨ A higher-priority client can end another thread's grace (the short window after a model finishes a turn during which it stays loaded in case a follow-up arrives) or idle-hot hold (the similar hold kept while a model sits idle) at the next turn boundary, so one caller can no longer extend its hold indefinitely with follow-up turns while a higher-priority request waits. The hold ends only when that resident is the manager's designated unload target, or when a strictly better-ranked request is already parked in that resident's own queue. A reply already generating is never interrupted.
- ✨ Inside one address, the traffic classes now rank against each other the way addresses rank among themselves, and the address always decides first, so a class rank never lifts one address above another; equal ranks are ties, served first-come-first-served. A same-thread follow-up inside the grace window no longer jumps a waiting request of the same address with a strictly better class, including one parked in the busy loaded model's own queue; a follow-up of an equal class keeps the warm path, and a running request is never affected.
- ✨ A waiting request with a better class can displace a loaded model of the same address that holds a worse class, under the same rules as between addresses: only at that model's own turn boundary, never mid-turn or mid-prefill, with the displaced model's context saved first when it can be and the other loaded models keeping their grace. When the manager picks which idle model to unload, the worse class inside one address goes first and recency only breaks a tie between equal classes; unlisted traffic still ranks below every listed address. A loaded model's class is the class of its latest request, including a follow-up served inside the grace window.
- ✨ A better-class request parked in a loaded model's own queue ends that model's grace at its next turn boundary, and the model's context is saved first when it can be. There is one waiting-request record per address and model, and it always carries the best request of that pair that is still waiting; it moves to the next best when that request starts, is cancelled, disconnects or fails, and is released when none is left.
- ✨ The `MAKE_ROOM_EVICTION` and `MAKE_ROOM_STARVED` log lines each end with `rank=<n>`, the class rank inside its address of the unloaded model or of the incoming request; `MAKE_ROOM_STARVED` reports `unresolvable` where its `rule_index=` is, while the eviction line's rank and rule index are read from two different identities and can disagree. Every earlier field and its order is unchanged.
- ✨ A Fast Lane census (`GET /api/fastlane/census`, surfaced under the Queue tab) lists every caller address the manager has actually seen and populates the Discovered table on the Fast Lane screen, so rules are built from observed traffic instead of guessed addresses, with addresses normalised exactly the way the matcher normalises them. The Queue tab and the dashboard now also report requests that are genuinely waiting, not just the queue's own depth: a table names each waiting request's client and the model it wants and marks which one a loaded model would give way to, and a separate table lists the Fast Lane claims currently registered, which is a different population because a claim can be raised before its request reaches the queue.
- ✨ The Fast Lane screen offers themed, keyboard-accessible rank pickers that save the instant a rank is chosen, renders one card per rule below the medium breakpoint with relative timestamps and 44px touch targets, and reports duplicate rules -- detected by normalised address, so two spellings of the same host are caught -- both when a config is saved and at startup.
- ✨ The same screen carries a **Counters** panel. One value, refusals by reason, is populated from the census; the other two, served and jumped per class and fairness firings, have no backend field yet and are rendered as `not yet available` rather than as a fabricated zero, so an unpopulated counter is a known gap rather than a fault.
- ✨ When a Fast Lane rule carries a saved label, that label appears on the request-identity line in both the Dashboard and the Queue view, read live from the rules, so a relabelled rule shows up without waiting for the next request.
- ✨ Every Fast Lane decision is visible in the log: request arrival, a declined pick (at debug level), an admitted-without-pick, a rule win as distinct from a fairness rescue, and a grace or idle-hot breakout.
- ✨ Fast Lane is documented for both audiences: the [README](README.md) explains what the feature does, its two priority levels and why it is safe to turn on, and the feature guide adds an API and config-file setup path alongside the UI one, including the read-only field a read-modify-write loop must strip before writing back.

**Plugins**

- ✨ A manifest can now describe a plugin as well as a model (`kind: model | plugin`), so an external container is registered alongside your models with its own `lane`, `capabilities` and `resource_key`; model discovery (`/api/tags`, `/v1/models`, `/api/show`) lists only real models, while `/api/manifests` lists both kinds and reports each row's kind.
- ✨ A boot-only endpoint registry maps each plugin's resource key to a container host and port -- so no manifest ever carries a URL or a filesystem path -- alongside a separate runtime section (enabled, maximum concurrency, no-progress timeout) you can change without a restart; a registry entry may name an `auth_token_file` for a plugin that requires authentication, a path to a file rather than an inline token, validated at boot so a bad path fails visibly instead of surfacing later as a confusing 401, and an optional `health_path` (default `/health`) naming the path the manager probes to decide whether the plugin's container is reachable, also validated at boot.
- ✨ `POST /api/plugins/{model_tag}/invoke` resolves a plugin's registered endpoint, calls the container and returns the result inline on the same request, mapping every failure onto one of five machine-readable reasons so a caller never gets a partial or empty answer. A plugin that stops responding is caught by a no-progress timeout rather than a call deadline.
- ✨ `GET /api/plugins` reports the routes and executables each plugin declares plus an invoke block giving the method, URL and body shape, so a caller can discover a plugin's capabilities instead of being told them out of band; each entry is reported as `configured` rather than as resolving, because nothing probes the plugin for reachability. A plugin manifest declares what it offers with two new keys, `provides_routes` (list of strings, empty by default) for the downstream HTTP routes it serves and `provides_executables` (list of strings, empty by default) for the bare binary names it can run, both validated as hostile input because anything able to write a manifest is able to write these lists.
- ✨ `WEBSOCKET /api/plugins/{model_tag}/exec` lets the engine run an allow-listed plugin binary transparently: a PATH shim runs a real local binary directly when one is baked in, and otherwise forwards the invocation to the plugin container, failing loudly with a non-zero exit and no partial output if the target dies mid-stream.
- ✨ A new Plugins tab lists every configured plugin with its lane, capabilities and whether its resource key resolves, plus the runtime knobs you can change without a restart; a plugin with no registry entry yet shows amber as "not configured yet" rather than red as an error.
- ✨ Video decoding now runs behind that interface instead of inside the image: `Dockerfile` and `Dockerfile.cuda-multi` install a small `ffmpeg`/`ffprobe` shim that execs an operator-baked binary if one is on `PATH` and otherwise forwards the invocation to a plugin container, while still images and audio remain compiled into the engine and `Dockerfile.engine-src` continues to install a distribution decoder.
- ✨ The resource-plugin (media hook) design is documented in [ARCHITECTURE.md](ARCHITECTURE.md) section 9.2 and a full [docs/MEDIA_HOOK.md](docs/MEDIA_HOOK.md), covering the CPU/GPU lane split, inline result delivery, the plugin manifest shape and its error behaviour.

**Models and blob store**

- ✨ **Model discovery now reports each model's context window, so a client can size a request without a restart.** `GET /v1/models` lists every installed model and `GET /v1/models/{model}` returns a single one, in the OpenAI-compatible shape a client expects: each entry carries `id`, `object`, `created` and `owned_by` alongside `context_length`, a `context_length_source` field, and a `turbohaul` object holding `display_name` and `multimodal`. A client that needs a model's context window can read it here instead of falling back to a built-in default, which is wrong for essentially every model this manager serves (#15).

  `context_length` is the context the model is configured for -- `llama_server_flags.ctx_size` where that flag is set, otherwise the manifest's own `context_size`. Check `context_length_source` before treating it as a guarantee: `"flag"` means an explicit `ctx_size` was set and llama.cpp was told to use exactly that; `"manifest"` means none was set, so the number is the manifest's declared `context_size` and llama.cpp is free to pick a different context of its own at load time. The field reports configured intent, not a promise in either direction, and nothing at this layer rejects a longer request. `multimodal` is derived from whether the model has a vision projector -- the same condition the manager uses to decide whether to launch one -- and the projector's own identifier is not published.

  Models hidden from discovery, and manifests that describe plugins rather than models, are omitted from these listings.

- ✨ **Both the versioned and the unversioned model-list paths are new: `GET /v1/models` and `GET /models`, and `GET /v1/models/{model}` and `GET /models/{model}` for a single model.** Each pair is served by one handler shared across both paths, returning identical responses; the unversioned prefix is a convenience for clients configured without the `/v1` prefix and adds no behaviour of its own (GitHub issue #15).

- ✨ **The Ollama-compatible surface gains a `modality` field.** `details.modality` in `GET /api/tags` and `GET /api/show` reports whether a model can actually serve vision, keyed on the manifest's declared projector (`mmproj_blob_sha256`) alone -- the projector is the only thing that reaches `llama-server`'s `--mmproj` flag (the raw `mmproj` flag is denied outright), so a bare vision-marker key in the model's own GGUF header is deliberately not treated as vision support, because a model advertised that way could not actually be launched with it. This matches `/v1/models`' `turbohaul.multimodal` (#15).

- ✨ `GET /api/blobs` enumerates the blob store for the first time, and the Models page is model-first: every model in the store gets its own tile, clicking a tile lists only that model's manifests, and the full manifest editor opens inline beneath the row it belongs to rather than at the top of the page.
- ✨ Models and manifests carry an editable free-text description, with model descriptions stored against the blob digest (`PUT /api/blobs/{digest}/description`) so they survive renaming or duplicating a manifest. Each manifest row also gains Duplicate and Rename controls: Duplicate copies a manifest to a new tag carrying its settings and description across, and Rename writes the new tag before removing the old one, so a failure part-way through leaves both tags in place rather than losing the manifest.
- ✨ The Models page refreshes as soon as the manager reports a manifest or blob change -- from another browser tab or another client -- and at least every 10 seconds otherwise, instead of only after its own edits or a manual Refresh.
- ✨ The Blobs tab gained search and sort, and model rows show details read from the GGUF header itself -- parameter count, size label, architecture, MoE flag and expert count, shown as Params, Type and Modality -- parsed off the request loop, so listing models on a cold cache no longer blocks in-flight streaming replies for seconds.
- ✨ A model can be kept out of the `/v1/models` and `/api/tags` discovery listings -- with `hidden: true` in its manifest, or the per-model Hide control on the Models tab -- while staying fully loadable and servable by its exact tag.
- ✨ `GET /api/manifests` is the management listing behind that control: it returns every manifest including the hidden ones, along with a `hidden_count`, and exists separately from the discovery endpoints precisely because those omit hidden models by design and so can never be used to manage visibility.
- ✨ `PATCH /api/manifests/{tag}` sets a single manifest field -- currently `hidden` only -- so a visibility toggle does not have to read-modify-write a whole manifest through `PUT`, which would race with anything else editing that model; any other key in the body is refused with a 400, and an `If-Match` revision that does not match the current one returns 412.
- ✨ `POST /api/manifests/{tag}/restore-defaults`, and a matching per-model control, drop one model's overrides for defaulted flags so it follows the shipped default again, showing which fields were cleared and that the change takes effect at the next model spawn, while deliberately leaving hand-tuned settings such as `ctx_size` and `tensor_split` untouched.
- ✨ `tensor_split` is an accepted manifest flag for setting the per-GPU weight split explicitly (for example `0.55,0.45`), parsed by a strict validator that rejects malformed, signed, scientific-notation and all-zero values, with the spawn refused when the number of entries does not match the number of visible GPUs. That device check is skipped when the GPU probe itself is unavailable.

**Front end**

- ✨ The live-inference panel now describes the whole machine rather than one engine: combined tokens/sec summed across every loaded model, a single combined sparkline, a split bar showing prefill and output at the same time because models really do prefill and decode concurrently, and an alarm banner that reports counts such as "1 stalled of 3 residents".
- ✨ The dashboard shows one card per loaded model -- each with its own tokens/sec, graph, split bar, state badge, live output box and countdown to the next state change, covering the grace window as well as the idle hold -- ordered stably so cards cannot flicker between refreshes, and a model that is resident but idle still gets a card so it never looks evicted.
- ✨ Each resident card shows the request that model itself last served, instead of every card echoing the single most recent request on the machine, and says so explicitly when it has served nothing.
- ✨ The dashboard reports context fullness both per resident and as an overall aggregate -- used, capacity and percentage beside a fill bar, turning amber from 75% through 90% and red above 90% -- so you can tell at a glance whether a fresh session or a compaction is warranted.
- ✨ A resident's live output box can be expanded to a taller view and collapsed again with a clearly labelled Expand/Retract button.
- ✨ Fast Lane is switched on from a Fast Lane card on Settings -> General -- the only place in the interface that enables it -- with an "Enable Fast Lane request priority" control, inputs for the anti-starvation wait and the cross-model switch rate, and a read-only view of the seven queue-section settings that share the policy, linking out to Settings -> Config -> queue.

**Configuration**

- ✨ `GET /api/config/schema` publishes every runtime setting with its type, bounds and default, and the Config tab renders a typed input per setting with per-setting reset-to-default, laid out in two columns on large screens with a clearly labelled Reset control.
- ✨ The schema and the Config screen now cover every runtime-mutable section the API returns -- queue, pull, Fast Lane, KV, persistence, monitoring, HTTP and plugin runtime -- instead of a short hardcoded list, so Fast Lane's own scalars (maximum normal wait, cross-model switches per minute, census TTL) finally have an operator surface rather than being writable only through the API. Those three render on Settings -> General rather than on the Config screen, which deliberately skips them.
- ✨ `GET /api/config` reports where each effective value came from -- shipped default, config file, environment variable, or a persisted runtime change -- and the server logs the divergences at startup.
- ✨ A saved config records which fields a save explicitly set, stamped in the config file itself, so a deliberately chosen value can be told apart from one that was merely filled in from a snapshot.
- ✨ Reasoning-scaffold stripping of the saved KV cache is a real setting (`kv.covered_scaffold_strip` in `turbohaul.yaml`, on by default) with a matching toggle in Settings, so a reasoning model's saved cache byte-matches what the client re-sends and tool-call turns reuse the cache instead of paying a full re-prefill.
- ✨ `queue.grace_ip_match_shared_addresses` (comma-separated string, empty by default) lists addresses known to be shared by several clients -- a container gateway, a NAT egress address -- and a request arriving from a listed address is refused an IP-based grace-window match. It fails open by design: an address that is not on the list still matches silently, so an operator relying on it has to list every shared address they know of.
- ✨ `queue.spawn_reclaim_wait_max_s` (float, default `10.0`) sets how long a spawn waits for in-flight VRAM reclaim to finish before it refuses outright; `0.0` restores the previous behaviour of refusing immediately.
- ✨ `queue.sidecar_complete_timeout_s` (float, default `3600.0`) is the timeout on a non-streaming sidecar completion call.
- ✨ The spawn safety gate now measures real host CPU utilisation rather than load average, and both halves of that measurement are settings: `queue.safety_max_cpu_busy_percent` (float, default `90.0`) is the ceiling, and `queue.safety_cpu_util_sample_window_s` (float, default `0.4`) is the window it is sampled over. The default is a saturation ceiling chosen as policy, not a measured optimum; the retired load-average metric was a per-core ratio on a different scale that does not convert to a percentage. The setting takes any value from `0.0` to `100.0`, where `0.0` refuses a spawn whenever the host is not perfectly idle and `100.0` disables the ceiling. The sample is host-wide rather than per-container, so the same one-core spike is a large share of a small host and a tiny share of a large one, and `iowait` and `steal` count as busy -- only `idle` is subtracted -- which makes the number run higher than a typical `top` CPU percentage on an I/O-heavy host. The sample window, bounded `0.05` to `5.0`, is re-sampled on every spawn attempt, so it is added latency on every attempt. Measure your own steady-state busy percentage under normal load and set the ceiling above it.
- ✨ `kv.ram_cache_max_age_hours` (float, default `6.0`) is the age ceiling for the RAM-tier KV cache, which was previously a fixed default on the cache collector with no operator surface.
- ✨ At startup the manager asserts that the KV cache directories sit on the filesystems they are meant to, and reports a mismatch loudly while continuing to serve: `kv.kv_save_expected_fstype` (string, default `tmpfs`, settable to null to switch that assertion off) asserts the fast tier really sits on its own tmpfs mount, and `kv.kv_persist_forbidden_fstypes` (list, default `["tmpfs", "ramfs"]`) is the inverse assertion, that the cold tier must never sit on one of those volatile filesystems.

**Speculative decoding**

- ✨ D-Flash and D-Spark join MTP as first-class per-model speculative-decoding types -- engine architecture and graph support, GGUF conversion, and a per-model config surface under its own **Speculative Decoding** heading in the manifest editor -- and configuring more than one model-based drafter now raises a named error instead of crashing inside the engine.
- ✨ `spec_draft_type_k` and `spec_draft_type_v` quantize the speculative draft cache independently of the model's own cache type, which previously always ran at f16 and could not be reclaimed.
- ✨ When speculation is downgraded at load time the dashboard shows it, so a model quietly serving without its drafter is visible in the UI rather than buried in the engine log.
- ✨ A manifest can now name its own speculative draft model with `spec_draft_gguf_blob_sha256` (string, empty by default). It is the way to point a standalone drafter -- the D-Flash or D-Spark draft types -- at a separate draft model: the digest resolves through the content-addressed blob store and the draft model is handed to the engine at spawn, while empty means no standalone drafter. Setting the field on a manifest whose `spec_type` is neither `draft-dflash` nor `draft-dspark` is accepted, logs a warning and records the downgrade on `/status`, so that model serves without speculation rather than being refused.

**Serving and capacity**

- ✨ **`reasoning_effort` on a chat request now sets the engine's thinking budget at spawn time, locked for that engine's entire life -- not per request.** llama.cpp's own thinking controls can only be honoured at process startup, and the previous release did not act on the field at all: a request carrying `reasoning_effort` had it silently ignored, so every model's thinking ran at whatever its manifest already asked for. `reasoning_effort` now resolves once, the first time a request causes a model's engine to spawn, against that model's own configured `reasoning_budget`: `low` a quarter, `medium` a half, `high` three-quarters, `xhigh` the full configured depth, `max` one and a quarter times it -- and is baked into that engine's launch flags for as long as it stays warm (#24).

  **`minimal` is not a value here.** It is a legal OpenAI value, but no value of this field was honoured before this release, so nothing is being taken away: a client sending `minimal` gets the same 400 an unrecognised value gets, deliberately -- measurement showed suppressing a model's thinking does not reliably make it answer faster, or at all, on every model this manager serves, and which model tolerates reduced thinking is an operator/end-user choice this manager cannot make on a caller's behalf. `low` is the floor.

  **First caller's effort wins.** Whoever's request first spawns a model's engine fixes its thinking budget until that engine is next reloaded. A later request asking a different effort on the same already-warm model silently receives the first caller's value -- a real, plausible answer still comes back, just not tuned the way that particular request asked. This is surfaced via a log warning and on the manager's resident status listing for whoever is watching either, but a caller who checks neither has no way to discover it. `xhigh`/`max` remain an extension beyond the OpenAI spec; a spec-following client using `low` through `high` is unaffected by their existence.

  **This applies at every `max_parallel_sidecars` value, the default of 1 included.** Every engine start goes through the one resident dispatcher, so the value resolved for the first request is baked into that engine's launch flags at any box budget.

  **There is no request-time `thinking_budget_tokens` conflict check.** A client sending both `reasoning_effort` and an explicit `thinking_budget_tokens` gets no 400 on disagreement -- the explicit value is simply forwarded, independent of whatever `reasoning_effort` says. There is no per-request resolved value for the explicit one to disagree with. A consequence of moving the resolution to spawn time, not an oversight.

  **On a manifest with no configured `reasoning_budget`, or one that sets it to `0` or `-1` (unlimited), no `reasoning_effort` value has any effect.** None of these is new behaviour and none is changed here; they simply mean that on those manifests the setting is inert.

- ✨ A single model tag can run multiple engine instances, one per GPU, with each session pinned to the instance already holding its cached context and any overflow queued rather than rejected; it is enabled by the host-wide `queue.max_parallel_sidecars` budget together with a manifest that sets `auto_place: true` and `llama_server_flags.split_mode: none`.
- ✨ A model that fits in VRAM but cannot start right away is queued and started when room appears, evicting idle models to make space, instead of being refused -- including the busy-engine case, which now waits in the queue rather than returning a 503 after 2.5 seconds.
- ✨ Interactive main-lane requests are admitted ahead of queued auxiliary work as soon as the engine frees, controlled by the new `main_lane_reserved` and `main_lane_identity_keys` queue settings; with the reservation disabled the queue is strict FIFO exactly as before (#10).
- ✨ Context-compression requests pop ahead of already-queued sub-agent work, so a conversation cannot grow unchecked while parallel work is still waiting.
- ✨ A `QUEUE_PRIORITY` log line names which class was served, why, and how many queued requests of which classes were skipped, so priority behaviour can be confirmed from the logs instead of inferred. The model-affinity exit deliberately logs nothing, so the count of these lines is a floor on picks, never a total.
- ✨ A host-RAM fit gate refuses a spawn when CPU-offloaded mixture-of-experts weights plus a RAM-resident KV cache would not fit in free RAM -- a combination that previously slipped past every existing gate and failed at load time instead.
- ✨ A model spawn is verified against the engine's own answer for which model it loaded, and the engine log is scanned for errors such as CUDA out-of-memory, so a spawn that silently degraded is no longer reported as clean.
- ✨ Status reports which model is inferring right now alongside the last one that did, and stays correct when more than one engine is allowed to run at the same time.
- ✨ When an engine dies the log carries a structured death record with identifying fields, and the dead-idle sweep names the fault it recovered from, so a mid-serving engine death is diagnosable and countable instead of being repaired silently.
- ✨ Engine processes log which inherited environment variables could override an explicit manifest flag, naming the variable and the rule that matched it -- names only, never values.
- ✨ A manifest whose thinking budget meets or exceeds its output ceiling makes the model burn its whole allowance inside the reasoning block and return nothing, so this is now caught in three places: saving such a manifest is rejected with the model and both numbers named, the per-model editor warns as you edit, and a request whose own `max_tokens` is the binding ceiling logs a one-off warning.

**KV cache**

- ✨ A save now keys off observed concurrency rather than the configured `max_parallel_sidecars` cap, so a box with idle sibling models no longer silently loses its clean prefix, and a model whose engine serves a single stream still restores its precomputed cache when it reloads instead of re-prefilling the prompt from cold.
- ✨ A long-running conversation keeps its precomputed cache when a short-lived request borrows the same engine. Previously the cache was written only on the idle-entry and teardown paths, never when one conversation handed the engine to another, so a sub-agent or curator turn that displaced the main conversation without unloading anything left nothing to restore from; that hand-off now saves the outgoing conversation's cache first. A compression turn is deliberately excluded, because it is about to rewrite the very context a saved copy would preserve.
- ✨ The memory tier is bounded by its own byte ceiling as well as by age and file count, so a burst of large conversations can no longer fill it and push out caches that are still in use.
- ✨ Every KV cache save, restore and classify decision announces itself in the log with a named reason, the tokens restored, a common-prefix percentage measured over shared turns rather than over tokens, a per-request correlation id, the exact turn at which a saved conversation first diverges from the incoming one, distinct labels for memory-tier and disk-tier saves, and distinct labels for completed, forced, timed-out, cancelled and errored end states.
- ✨ The sidecar support that was already there is now extended to the restore side: the engine persists a slot's checkpoint ladder to a `.ckpt` sidecar on save (`TURBOHAUL_CKPT_SIDECAR`) and this release reloads it on restore, so a cold-restored conversation keeps its fallback rungs instead of paying a full re-prefill on any divergence; with the flag unset behaviour is unchanged.

**Documentation**

- ✨ A screenshot-led handbook for the web interface ships under `docs/frontend/`: one page per tab -- Dashboard, Queue, Fast Lane, Blobs, Models, Plugins, Settings -- plus an index, for readers who would rather see the current layout than read release notes. Also new: an operator walkthrough for registering and calling a plugin ([docs/PLUGINS_SETUP.md](docs/PLUGINS_SETUP.md)) and a complete field reference covering every manifest field, registry field, runtime knob, endpoint and failure reason ([docs/PLUGIN_REFERENCE.md](docs/PLUGIN_REFERENCE.md)).

- ✨ New guides for the KV cache: the RAM and disk lifecycle, the `ctx_checkpoints` and turbo KV-quant defaults with their size-against-accuracy trade-off, what each turbo cache type is and the two cases where the engine overrides the type a manifest asks for, how to verify which type is actually in use, and the case that had no coverage at all -- getting exactly the type you asked for and still getting incoherent output from a healthy-looking server, with an f16 control run as the load-bearing verification step.

**Operator escape hatches**

- ✨ The guards this release adds are decline-only, and each can be switched off from the environment: `TURBOHAUL_CLEAN_STAMP_EVIDENCE_GATE` (on by default) refuses a forced clean KV save that has no recorded think-free render evidence, `TURBOHAUL_COLD_RESTORE_SIZE_GUARD` declines a saved cache whose recorded token count exceeds what the incoming request renders, `TURBOHAUL_COLD_RESTORE_TOOLS_FINGERPRINT_GUARD` declines a cold restore whose saved conversation used a different tool set, and `TURBOHAUL_STALETAIL_RESTORE_SKIP` applies the stale-tail trim to a warm checkpoint restore. Setting any of them to `0`, `false`, `no` or `off` returns the previous behaviour.
- ✨ Turning off `TURBOHAUL_CLEAN_STAMP_EVIDENCE_GATE` is a correctness rollback and not a performance lever: the stamp it replaces marked a cache clean on a slot-count fallback, which covers reasoning tokens the client never re-sends, and caches written under it are the ones that restore into incoherent output. Turn it off only to isolate an engine build that has regressed, never to raise save throughput.
- ✨ `TURBOHAUL_TOOLTAIL_RESTORE_SKIP` and the covered-scaffold-strip setting are coupled, and nothing in the code enforces the coupling. The variable (off by default) is the compensating switch, and it must be set on if `kv.covered_scaffold_strip` is ever turned off: its default-off posture is safe only while scaffold stripping is on by default. Enabling it is a blunt containment measure, not a clean-correctness path -- it reverts to scanning only the appended tail, so a fresh tool-heavy tail still over-skips and forces a full reprocess instead of the cheap clean-restore reuse.
- ✨ `TURBOHAUL_GRACE_IP_SHARED_ADDRESSES` is the environment-variable form of `queue.grace_ip_match_shared_addresses`, for an operator who supplies that list through the environment rather than the config file.
- ✨ `EXEC_PLUGIN_AUTH_TOKEN` is an optional outbound bearer credential the plugin exec bridge sends to a plugin container. It is a different variable from the per-plugin `auth_token_file` an endpoint registry entry may name: that one is the credential a plugin presents, this one is the credential the manager presents to the plugin.

**Serving and engine**

- 🔧 The vendored inference engine takes on a 24-commit stability and correctness backport -- 22 from upstream `llama.cpp`, 2 developed here -- mixture-of-experts and speculative-decoding crash fixes, CUDA and CPU kernel correctness, server request and streaming handling, multimodal prompt handling, and fixes for two model architectures. The per-commit detail, with an upstream reference for each, is in [docs/ENGINE_CHANGELOG.md](docs/ENGINE_CHANGELOG.md). No manifest, flag or configuration change is required.
- 🔧 The engine is built from vendored source, and that build path is checked (see the guard below). A prebuilt self-contained image is also published as a convenience, and it is not guaranteed to match this source, so build from source when the engine in the running image has to be the one in this repository.
- 🔧 A new build-time guard refuses a build outright when the engine library is missing, empty, mismatched, or lacks asymmetric KV-cache support, so an image that boots healthy and dies on the first context save is never produced; an overlaid engine carrying an unexpected cache-quantization variant is warned about.
- 🔧 `hybrid_kv_ratio` is read from any model that declares it rather than being applied only to one hard-coded architecture, so any hybrid model still sizing off the legacy file-size path gets the reduced per-token KV estimate, announced once per model in the log instead of on every request. A model that resolves its own attention dimensions, or that carries a measured `kv_bytes_per_token`, already discounts correctly on its own path and ignores the ratio.
- 🔧 The `Retry-After` returned with a 503 is derived from the model load timeout the server actually enforces, so a client that obeys it no longer retries into a model that is still loading.
- 🔧 A conversation's cache is written to the SSD cold tier only when the model idles out or shuts down, no longer on every live model swap, and every SSD-persist log line names the trigger that produced it.
- 🔧 KV checkpoints move to format v3, so a draft sidecar written by an older engine is cleanly rejected rather than restored into an incompatible rotation.
- 🔧 The per-model `max_instances` manifest key is not a cap any more: v0.7.0 rejected it as an unknown key, so a manifest or `PUT` body carrying it was a validation error, and this release accepts it, drops it with a warning, and rewrites saved manifests without it once, at the first start. How many engines one model runs now follows the host-wide `queue.max_parallel_sidecars` budget and the cards the model fits on; a second engine of one model needs `auto_place: true` and an explicit `llama_server_flags.split_mode: "none"`, and a model without both keeps one engine; windows per engine are still `llama_server_flags.parallel`. See [docs/SIDECARS_AND_CONTEXT_WINDOWS.md](docs/SIDECARS_AND_CONTEXT_WINDOWS.md).
- 🔧 When a second engine of a model is refused by a host safety gate, fails to start or fails to load, the request is now served by the engine of that model that is already running instead of failing (an out-of-memory load failure, with the client still connected, goes back in the queue as before). A cold start, where no other engine of the model is running, fails as before, and so does a request whose only other engine cannot take it yet, for example while it waits for VRAM to be freed before it starts. See [docs/SIDECARS_AND_CONTEXT_WINDOWS.md](docs/SIDECARS_AND_CONTEXT_WINDOWS.md).
- 🔧 The Discovered list on the new Fast Lane screen has a Name column that shows each client's container name once the manager has confirmed it: the name is looked up in the background, and it is shown only when a forward lookup of that name returns the client's own address, so a name that stops matching is dropped. The name is for display only and is never used to match a request. Add to Fast Lane on a named client saves the rule by container name, so it keeps matching when the container restarts and gets a new address; a client with no name saves by address. Fast Lane lint warnings number rules from 1, the way the screen does.

### Fixed

- 🐛 **A manifest that fails validation no longer crashes an inference request.** A model whose manifest violated the schema -- an unknown field, a typo, an unreadable file -- previously produced a bare `500 Internal Server Error` with no explanation on chat completions and on embeddings. The error class those routes caught is a sibling of the one actually raised, not its parent, so it never matched. Both of those routes now answer with a deliberate message that names the model and does not echo manifest content, and plugin invocation answers the same way. Discovery and listing behaviour is unchanged: a listing still skips an unreadable manifest and keeps serving its healthy siblings. Validation itself is unchanged -- an unknown field is still rejected. (#19)
- 🐛 Reusing a warm slot could answer a request with a different caller's conversation and stamp an unrelated caller's session identity and origin address onto it, which also sent the wrong cached context; outbound content now comes from the request itself, and identity is inherited only for a genuine same-session or same-thread continuation, never merely because both callers arrived without a session id. (#16)
- 🐛 A conversation that ends with two or more assistant messages in a row no longer permanently poisons the slot, rejecting that request and every request after it even across a manager restart; such a run is collapsed into one message before the request reaches the engine, and well-formed conversations are untouched.
- 🐛 Long non-streaming completions no longer die at ten minutes: the completion timeout is a real configurable setting, defaulting to one hour at parity with streaming, instead of a hard-coded 600 seconds no operator could raise.
- 🐛 An Ollama-style chat request sent with `stream: true` no longer hangs for up to an hour and then returns a placeholder instead of the model's reply -- that endpoint has no streaming path, so it completes immediately as a normal non-streamed response.
- 🐛 Non-streaming chat completions no longer silently drop most request knobs -- the token cap, the sampler penalties, seed, mirostat and the reasoning budgets -- so a non-streaming request honours the same limits a streaming one does.
- 🐛 A manifest reasoning budget larger than the caller's `max_tokens` is now clamped per request with an answer floor reserved, so a reasoning model no longer spends its entire allowance thinking and returns an empty answer.
- 🐛 The chat and embeddings endpoints no longer reject inline multimodal input with a 413 before it reaches the engine: two hard-coded ~2 MiB body ceilings are replaced by one configurable limit (`http.max_body_bytes`, or `TURBOHAUL_MAX_BODY_BYTES`) defaulting to 64 MiB, which is enough for a base64-inlined short video.
- 🐛 A teardown that dies partway through can no longer leave a card permanently believing memory is about to come back, which had stopped that card evicting anything ever again and made every later request defer and then 503 until a restart.
- 🐛 Spawning a model no longer crashes before any safety gate runs, and VRAM is charged only against same-card siblings that are still loading rather than every resident on every card, which double-counted already-loaded models and could wrongly refuse a spawn that fits.
- 🐛 VRAM-fit placement now reconciles a model's real allocation after loading, and a queued request already listed for a slot is no longer evicted out from under it.
- 🐛 A streaming request whose model failed to be placed now returns an error immediately, instead of leaving the connection open and hanging indefinitely with nothing to interrupt.
- 🐛 Capacity failures now return one typed error shape on every path -- streaming and non-streaming, chat and embeddings -- carrying the cause and a consistent `Retry-After`, where `/v1/embeddings` could block for the full 7200 seconds and then mislabel the result, and its capacity failures fell through to a generic 500, the streaming error frame dropped the retry hint entirely, and streamed errors were truncated at 500 characters.
- 🐛 An embeddings request that loses a capacity race no longer wedges indefinitely with no status and no body.
- 🐛 When an engine's driver dies the caller now receives the real 503 with `Retry-After`, or a 504 on a timeout, instead of a generic 500.
- 🐛 When a model process exits, a request it had already answered no longer comes back as an error, and a request it abandoned before serving no longer hangs forever -- that one always returns a visible error naming the model.
- 🐛 A request queued for a different model is no longer held behind a model sitting in its grace window: starvation is detected anywhere in the staging queue rather than only at its head, and detecting it ends that grace window early instead of letting it run out its full length, so an ordinary queued request can cut a resident's hold short. A request carrying a Fast Lane claim is excluded from this path and cannot end another resident's grace this way. (#23)
- 🐛 A slow prefill probe can no longer stall request processing: the shadow-prefill probe, which inherited a 15-minute read timeout, is now bounded at 180 seconds, and the model-swap probe already was, and a probe timeout is logged distinctly from an engine error or a bad render.
- 🐛 A request that omits `keep_alive` no longer cancels a `keep_alive` set explicitly by an earlier request, so a model told to unload immediately no longer stays resident.
- 🐛 A single unreadable manifest on disk -- broken YAML, one written by an older version that no longer matches the schema, or a file that is not valid UTF-8 -- no longer fails model discovery, the manifest, blob or plugin listings, or a blob delete: the offending file is named and skipped, every other model still lists, fetching, patching or restoring defaults on that one manifest returns a 400 with a reason instead of a 500, and a delete that had already removed the blob no longer reports failure for work it completed.
- 🐛 Settings changed at runtime now survive a restart or a container recreate, written to a persisted override file loaded on top of the defaults at boot, and the monitor section is editable at runtime instead of being rejected.
- 🐛 Saving settings through the config API writes only the fields actually changed, so one change no longer freezes every other runtime-tunable setting on disk and silently disables its environment-variable override.
- 🐛 Conversations that use tool calling no longer reuse a saved context that has already diverged: tool-call payloads are now part of the conversation fingerprint, and a saved context whose tool set differs from the incoming request is declined instead of restored.
- 🐛 An unload never cuts a running turn for any client: a resident that is mid-turn, including mid-prefill, is torn down only at its turn boundary, even when it was designated as the victim earlier and then accepted a follow-up.
- 🐛 A follow-up that a resident had taken out of its inbox but not started is no longer lost, or failed, when the resident is unloaded at that moment; it is re-queued and served later like any other drained follow-up.
- 🐛 When the automatic placer finds no single card that fits a model, the model is no longer split across the cards while idle models on one card could be unloaded to hold it whole: the manager now counts the idle models on each card as free memory first, places the model on the card that fits (unloading those idle models, cache saved first when it can be, never cutting a turn), and uses a layer split only when no card fits even with that reclaim (not while a split model is loaded). When several cards fit, it picks the one whose idle models are least protected, so a lower-priority client's idle model is unloaded before a higher-priority client's (inside one client the model with the worse class is unloaded first), and only cards equal on that fall back to the fewest MiB freed.
- 🐛 Such a request is never started by the shortfall path itself: it unloads one idle model on its chosen card (never one on another card, and never a second while the first unload already covers the memory), waits for the next pass and is started by the normal placement once the card has room, and at the model-count limit with that memory already on its way back any idle model frees the count slot in the usual order. It applies to every request the automatic placer decides, never moves a model whose manifest is itself split, and keeps the roughly 1.3 GB of CUDA context a one-card model leaves on the other cards clear of the safety floor. The starvation log line now carries `card_scope=` (`all` for requests that look at every card).
- 🐛 A resident with nothing left to serve no longer stays recorded as actively serving, which left it invisible to eviction and starved competing queued requests for minutes at a time: it now goes idle and can be evicted to make room for another model.
- 🐛 The spawn safety gate no longer refuses a model that fits because of load average, which counts tasks blocked on disk rather than cores doing work and read high on an otherwise idle box. Admission now measures real CPU utilisation, so a spawnable model is no longer rejected.
- 🐛 The idle countdown a model sits in after finishing a request no longer runs down while that model is still answering one: it pauses during active generation and resumes from where it stopped, so a model serving a long request is no longer shown as about to be unloaded.
- 🐛 With automatic fitting on -- the default -- a standalone drafter was silently dropped and the model served with no speculation for the life of the process; the draft-memory measurement now runs correctly and the drafter loads.
- 🐛 On a default single-engine deployment the reaper now actually cleans up, because ordinary cold spawns record their engine identity; co-resident engines are no longer terminated during teardown and idle reaps; and the stale-listener diagnostic no longer silently reports zero. (#9)
- 🐛 A clean engine stop is no longer recorded as a crash -- a CUDA cleanup failure during shutdown no longer aborts the process -- and the log line naming why an idle engine died is written whatever the parallel-engine limit is set to, and was never emitted there.
- 🐛 The live monitor no longer reports an idle box while it is actually serving: at the default setting, where only one engine runs at a time, it previously reported the box as idle no matter what the engine was doing, and it now reports each resident's real state at every setting.
- 🐛 A vision projector no longer launches on the wrong card: it is now pinned to the model's own GPU, and a hand-set device override that disagrees with the model's GPU is reported in a warning naming both values.
- 🐛 Deleting a blob that manifests still point at is refused with a 409 listing every referencing manifest and the field that matched, so a vision projector or speculative draft model used only by other manifests can no longer be destroyed by a Delete button that showed it as an empty model.
- 🐛 KV-cache sizing now caps sliding-window layers at their window instead of counting or ignoring them wholesale, and reads exact expert placement from the model file's tensor offsets, so sliding-window and mixture-of-experts models are no longer admitted on an under-estimate and then run out of memory.
- 🐛 Models running MTP speculative decoding are no longer admitted into VRAM they cannot fit: the safety gate now budgets the speculative draft context's KV cache in addition to the main context, closing a class of out-of-memory failures that hit even with nothing else loaded on the card.
- 🐛 After a cache-identity collision on a shared slot the manager restores a verified pre-collision snapshot and logs that it did, falling back to a full re-prefill only when the restore cannot be verified against the engine.
- 🐛 With Fast Lane on, a higher-priority request waiting in an already-loaded model's inbox now counts as waiting; before, it was invisible, so a lower-priority client's rapid follow-ups could win indefinitely (tens of minutes were observed). The holder's grace now ends at its next turn boundary, its KV state is saved, and the waiting request is served next on the same loaded model with no reload; the holder's follow-up is queued behind it, never dropped. A running reply is never interrupted, equal or lower priority never jumps the queue, and the waiting request stays in the queue view, its place is given up if it is cancelled or the model dies, and a request whose client has disconnected is passed over when another request can be served instead.
- 🐛 A resident whose engine dies mid-turn now wakes the waiting claimant at once instead of leaving it to the retry timer.
- 🐛 D-Flash drafters were rotated with the wrong RoPE convention, so only about 2% of drafted tokens were accepted and speculation was slower than running without it; acceptance and throughput now match the reference implementation, with no change when no drafter is configured.
- 🐛 A standalone D-Flash or D-Spark drafter no longer aborts the process on its very first decoded token, and requesting one on an architecture that did not export per-layer hidden states no longer aborts the whole server -- the capture hook is now present on the qwen3.5, qwen3.5-MoE and qwen2 builders.
- 🐛 A model declaring a missing or invalid draft block size is refused at load with a clear error, instead of either killing the server outright or silently running speculative decoding that never produces a draft.
- 🐛 A manifest that sets more than one parallel slot is no longer refused for a context split that does not apply to it: the checks that rejected a context size which did not divide evenly across the slots, or which left each slot below the minimum usable window, applied only to a split that cannot happen now. A manifest that runs more than one slot must set a unified KV pool, and that requirement is checked first and refused if missing; with the pool, every slot is given the full context size rather than a share of it, so a context size that does not divide evenly across the slots is accepted.
- 🐛 Offline engine image builds no longer fail on a missing prebuilt web-UI asset; the upstream prebuilt-UI download is disabled, since the project ships its own front end. (#8)
- 🐛 Status output no longer reports a model's loading elapsed time as zero through an arbitrarily long stall, and grace and idle-timeout changes made through the config API now reach already-resident models on their next turn.
- 🐛 Every reasoning block inside an assistant turn is stripped before a cache is saved, not just the first, so a reason/tool-call/reason/answer turn no longer produces a cache the engine throws away on the next cold restore; reasoning inside user or tool content is still left untouched.
- 🐛 Saved caches are truncated at exactly the point the client's next request will resume from rather than at the slot's raw prompt length, so a just-generated turn's stripped reasoning no longer causes the engine to discard the entire cache on restore, and the engine's reported effective token and byte counts are logged beside the limit that was requested.
- 🐛 A saved cache is no longer overwritten by one that is not actually newer -- the overwrite decision follows the content chain rather than treating token count as a proxy for freshness -- while a context-compression pass that legitimately shortens a conversation can now save, instead of keeping the stale larger copy and stranding the session with none it can use.
- 🐛 A forced restore is declined when the slot already holds more of the conversation than the saved copy does, and a stale saved context can no longer overwrite a larger live context and force a full re-prefill.
- 🐛 A restore on the cold path, or of a context coming back to service, declines a saved context far larger than the incoming prompt, instead of restoring it and leaving the engine to clear and re-prefill anyway.
- 🐛 Clearing a KV sequence after the recurrent-state bound is exceeded now also clears that slot's checkpoint ladder, so a stale checkpoint can no longer be selected on a later request and silently loaded on top of a completely different prefill.
- 🐛 A warm checkpoint restore runs the same stale-tail trim as a cold restore, so a slot no longer retains the previous occupant's cells at positions about to be written and then writes that dirty state to disk. (#18)
- 🐛 A context is no longer saved as clean while the engine still holds leftover cache cells from a failed restore or an adapter change, because occupancy is read from the cache itself rather than from the in-memory token list.
- 🐛 Three incomplete-cleanup paths left the dirty-tip guard disarmed, so a later save could run against a port that had not been fully remediated; the guard is now re-armed on all three.
- 🐛 Caches saved under different speculative draft lengths are no longer indistinguishable -- the cache fingerprint records the engine's real recurrent-sequence count instead of the slot width -- with a one-release grace period that re-stamps existing caches rather than discarding them.
- 🐛 A conversation's cache is no longer erased and forced into a full re-prefill when the save that erase was preparing for would have been refused anyway by checks that only ran afterwards.
- 🐛 A conversation's cache saved at model unload is no longer filed under a visiting model's name, where the conversation itself would never look for it again, and a request that arrives with its own session classification no longer inherits the previous occupant's label.
- 🐛 A background helper that reuses the main conversation's session id no longer convinces the scheduler that the main conversation's tokens are still resident, which had it report cache reuse that was not happening and skip a restore it actually needed.
- 🐛 A conversation parked at the end of its grace window is saved at the last turn actually served rather than at the turn that opened the window, so restoring it no longer drops back to the first call.
- 🐛 Verifying a KV restore no longer races the engine: the restored token count is read from the restore response itself instead of a follow-up slots query that can report nothing in the instant after a restore.
- 🐛 The KV-restore verification result is a real comparison of expected against actual tokens rather than a status that defaulted to success, so a run can no longer be recorded as proof that restores worked when nothing was ever compared.
- 🐛 Saved contexts on disk are now read back on a cold start, so restarting after the in-memory tier emptied no longer pays a full re-prefill despite a complete copy being on disk.
- 🐛 Clearing a conversation's cached state now sticks, instead of the identical file being copied straight back from the disk archive on the next cache scan.
- 🐛 Repopulating the fast RAM cache tier from the disk archive now happens only for the conversation actually being requested, rather than sweeping the entire archive on every cache scan.
- 🐛 The KV cache is now saved whenever no other model is actually serving, rather than being skipped on any server merely configured to run more than one model in parallel, so cached-prompt reuse works on multi-model hosts.
- 🐛 While a model is loading in, the dashboard now shows a loading card instead of nothing at all: the incoming model is reported during the window in which the manager reserves the memory it needs, so a load in progress no longer looks like an empty screen.
- 🐛 The card for a model being swapped out no longer goes blank: it keeps showing the outgoing model's name in the unloading state until the card's memory actually drops, instead of showing nothing in between.
- 🐛 The Residents card no longer contradicts itself: the detail row is labelled as the last request rather than the resident's identity, is flagged when that request went to a different model than the card it sits on, distinguishes a sub-agent's curator from the resident's own, and shows a dash instead of a misleading zero for missing cache, process and port values.
- 🐛 The KV restore indicator tells apart restored, not restored, nothing to restore and genuinely unverified, instead of labelling all four as unverified, and the prefill meter shows no reading when nothing is prefilling instead of dropping to 0% and flickering as models move between prefill and decode.
- 🐛 A model that is simply busy serving traffic no longer counts as an alarm or turns the dashboard banner red, which had it flickering on and off with ordinary traffic.
- 🐛 Refreshing the browser no longer collapses the dashboard back to a single live-output box -- each resident streams its own output from the moment the page loads.
- 🐛 The per-model flag editor no longer renders the five primary flags that live outside the Common category (`cache_type_k`, `cache_type_v`, `temp`, `top_p`, `spec_type`) twice, and no longer hides a non-primary flag that falls inside it.
- 🐛 The app no longer scrolls sideways on a phone: the header stacks below the small breakpoint instead of forcing the title and all four nav links onto one row, nav links wrap, nav and sub-tab targets meet the 44px touch minimum, the active link is announced to screen readers, and the combined-throughput sparkline stacks full-width beneath its figure instead of being squeezed into a sliver that shrank further as the number grew longer.
- 🐛 The Models page fits a phone: manifest rows are taller and carry the manifest's own name so you can tell them apart without opening one, every control meets the minimum touch size, buttons wrap instead of pushing the page wider than the screen, and a narrow screen stays in one column.
- 🐛 Telemetry now records a dispatch event for every turn, including warm reuse, which splits the delay between a request arriving and its first token into wait time and prefill time. Non-streaming requests, which previously had no per-turn measurement at all, are now covered.
- 🐛 Admission stalls can now be diagnosed from the log alone: the line reporting that not enough VRAM could be freed names per-GPU utilisation and VRAM for every card, as well as the requesting client's traffic class, so a genuinely busy box can be told apart from a stuck one.
- 🐛 The reuse log line no longer reports unavailable token fields on classification decisions, decision and outcome lines can be joined on a single request identity, and divergence captures are actually written to disk instead of failing silently when the target directory does not exist, with write failures surfaced as errors.
- 🐛 The manager's own once-a-second internal poll no longer floods the log, where it had accounted for over 90% of all lines, and the queue's per-decision decline messages now log at DEBUG rather than firing on a fixed 50ms cadence regardless of traffic.
- 🐛 Engine crashes now always print a backtrace, instead of only when no abort handler is installed.
- 🐛 Lifecycle audit events reach the live event stream correctly when they are published from the manager's background worker thread rather than the server's event loop.
- 🐛 A manifest can set a log verbosity of 5 to reach the engine's debug level; the accepted range was capped one step below it, making debug logging unreachable.
- 🐛 The server warns the moment a conversation's tool set changes between turns, naming which tools entered and left -- the condition that silently invalidates a saved context and forces a full re-prefill -- and it fires on every turn shape.

### Security

- 🔒 An engine process is killed only when its live (pid, port, start time) identity matches one the server recorded at spawn -- port scans and parent-PID heuristics now only nominate candidates, and an unrecorded or foreign process is reported and left running, removing the risk of terminating an unrelated process after PID reuse. (#9)
- 🔒 Plugin endpoint registration rejects shorthand IP spellings of loopback such as `127.1`, `2130706433` and `0177.0.0.1`, which the OS can expand to reach the manager's own API. This guard ships with the new plugin subsystem. A loopback address written plainly registers but is refused when the plugin is called: the invocation fails with a blocked-target error, the plugin is listed as not configured, and the exec bridge refuses the upgrade as well. The guard covers IP literals only and does not resolve hostnames, so a name such as `localhost` is not blocked by it.
- 🔒 Plugin invocation errors name the resource key and the reason only -- the client-facing error does not disclose the registry's internal host and port, or raw exception text -- while the full diagnostic goes to the server log. This ships with the new plugin subsystem.
- 🔒 The persisted runtime-settings file can only supply runtime-mutable sections at boot, so a tampered file carrying boot-only sections -- one repointing the inference binary, for instance -- is ignored rather than applied; the config endpoint already returns 403 for those fields.

### Known issues

- 🚧 **The disk-tier KV cache save is not working, with one exception.** Writing the cache to disk when a model is unloaded is work in progress and does not currently happen for any unload reason -- idle expiry, shutdown, a make-room release, grace expiry, or a load failure -- so a cache will not be found on disk after an unload, and will not be restored from disk on the next load: a restart or a container recreation loses it. The RAM tier is unaffected, so a reload inside the same container still restores from memory, and a model-swap hand-off still passes its cache to the incoming model.

### Compatibility

Six things differ for an operator coming from v0.7.0. Two are reported when they happen rather than applied silently, one changes the shape of a response body a client reads and lengthens the retry hint sent with it, two change behaviour with no message at all, and the first refuses to start a manager that was not prepared for it at all.

- ⚠️ **A retired queue setting will stop the manager from starting, and will keep stopping it until the file is edited.** `safety_max_load_per_core`, the load-average-per-core ceiling an existing configuration may still carry, is retired and replaced by `safety_max_cpu_busy_percent`, a percentage of host CPU busy that defaults to `90.0`. Both keys live under the `queue:` section of the file, so a `safety_max_cpu_busy_percent` written at the top level instead is a second, different validation failure rather than a fix. The configuration model rejects keys it does not recognise, so a file that still carries `safety_max_load_per_core` is a validation error when the manager loads it, and the manager does not start. The startup path recovers from problems in the Fast Lane section only; this is not one of them, so nothing inside the running system repairs it. In a compose-style deployment the container restarts against the same configuration file, mounted read-only, so the failure repeats on every restart until someone edits that file by hand; someone running the binary directly has no restart policy and sees it once, on their own next start. If you ever saved a change from the Settings page in v0.7.0, the same key is also in `runtime_config.yaml`, the saved-settings file next to the state database (`/var/lib/turbohaul/runtime_config.yaml` by default); remove it there too, or the manager still will not start. Deleting the retired line is enough to boot: the shipped default configuration carries neither key, so removing it lands on the documented `90.0` default and setting the new key is optional. There is no environment variable for either key, so unlike the neighbouring settings that have one, the only place to make the change is the file. `0.9` was a load average per core, which counts tasks waiting on disk as well as cores doing work; `90.0` is a share of CPU actually busy. They do not convert, so re-derive the number for your own host rather than translating the old one. There is no configuration dry-run or check mode, so the practical procedure is to search both files for `safety_max_load_per_core`, delete the line, then start the manager once in the foreground and read the message: this is a startup validation error that names the offending field, not a silent degradation, so what to change is in the error itself.
- ⚠️ **The 503 for an unavailable engine now carries an object where it carried something else, and its `Retry-After` is now longer.** On the chat-completions and chat endpoints, a sidecar being unavailable used to answer with `"error": "sidecar_unavailable"`, where the `error` field was a string. On the embeddings endpoint it used to answer with a bare string body and no `error` field at all. All of them now answer with `"error": {"type": "sidecar_unavailable", ...}`, where the `error` field is an object carrying a type, a cause and a message. A client that compares the `error` field against the string stops recognising this error on the chat endpoints and has to read the type from inside the object instead; a client that reads a type out of the embeddings body finds nothing there and has to look inside `error` too. The status code is still 503, but the `Retry-After` sent beside it is not what it was. On the chat endpoints it used to be the exception's own value, 30 seconds by default, and is now the larger of that value and the model load timeout the server enforces -- 60 seconds on the code default, 120 on the shipped configuration -- so a client that honours it waits roughly twice as long there, and up to four times as long on the shipped configuration. On the embeddings endpoint the sidecar-unavailable path used to send a fixed 5 seconds and now sends the exception's own value, 30 seconds by default, while a shutdown-time path there still sends a fixed 5.
- ⚠️ `reasoning_effort` is now validated and honoured; v0.7.0 ignored the field entirely, so no value was applied before. This release accepts `low`, `medium`, `high`, `xhigh` and `max`, and any value outside those five -- `minimal` among them -- is refused with a 400. `minimal` is still a legal OpenAI setting, but a client or manifest that asks for it has to ask for `low` or higher. A request that asks for `minimal` fails rather than being served with some other effort.
- ⚠️ v0.7.0 rejected `max_instances` as an unknown key, so a manifest or `PUT` body carrying it failed validation; this release accepts it, drops the key and logs a warning. How many engines one model runs follows the host-wide `queue.max_parallel_sidecars` budget instead of the manifest, and a saved manifest is rewritten without the key at the first start.
- ⚠️ `TURBOHAUL_COVERED_SCAFFOLD_STRIP` is now inert, so a deployment that sets it in the environment gets different behaviour and no error. It used to be the control for the cache-save reasoning-scaffold strip, defaulting to on unless set to `0`, `false`, `no` or `off`; the `kv.covered_scaffold_strip` setting replaces it and still defaults to on. A deployment that was setting the variable to `0` gets the on behaviour back with nothing logged about it, and has to move the value into the `kv` section to keep it off -- in the configuration file, through the config API, or with the Settings control, since that section is runtime-mutable.
- ⚠️ KV checkpoints move to format v3, so a checkpoint sidecar written by the previous release is refused instead of restored. This applies to deployments that have the checkpoint sidecar enabled; if it is not enabled there is no sidecar to refuse. The format version is recorded in the sidecar and checked on read, so an engine built from this release rejects a sidecar written by v0.7.0 rather than reading it into an incompatible rotation, and the conversation behind it falls back to a full prefill. Nothing in the manager reports the refusal to the client; it shows up as a conversation that has to be rebuilt.
- ⚠️ For an operator upgrading from v0.7.0, those are the six things to look for. Remove `safety_max_load_per_core` before the first restart, from the configuration file and, if you ever saved settings from the Settings page, from `runtime_config.yaml` too, or the manager will not come up; a client reading an unavailable-engine 503 has to read the type from inside the `error` object, and has to expect a longer `Retry-After`; `minimal` has to become `low` or higher; `max_instances` is ignored from now on, so deleting it is optional; `TURBOHAUL_COVERED_SCAFFOLD_STRIP` has to become a `kv` section setting if it was being relied on; and checkpoint sidecars written by the previous release are refused rather than restored.

## [v0.7.0] - 2026-07-23

### Highlights

- **Hybrid state-space/attention models now serve end to end.** The manager gains manifest fields for describing a hybrid architecture plus a dimension-aware KV-fit estimate, so a `qwen35` hybrid loads and serves through the same single, series-parallel, and double-parallel paths as any other model. The addition is strictly additive: every existing model is byte-for-byte unchanged, and no existing deployment has to change anything to keep running as before.
- **Large contexts on hybrid models are no longer refused for a phantom shortfall.** The old estimate derived a hybrid's KV cache from its file size, which assumes every layer grows a cache per token. On a state-space hybrid that over-counts badly — in one measured case by roughly 3.4×, enough to refuse a 250,000-token context that in fact fits comfortably. The dimension-aware estimate reads the model's real attention dimensions instead, and an operator can override it outright with a measured figure. See [docs/SAFETY_GATE_VRAM_MATH.md](docs/SAFETY_GATE_VRAM_MATH.md).
- **Multi-GPU placement is now automatic.** Co-resident models can be spread across cards instead of piling onto the manifest's pinned default, with per-card VRAM accounted separately so one card's headroom is never mistaken for another's. See [docs/MULTI_GPU_PLACEMENT.md](docs/MULTI_GPU_PLACEMENT.md).
- **Vision models are supported.** A vision projector is supplied as a content-addressed blob, keeping the path-bearing raw flag denied. See [docs/VISION_MODELS.md](docs/VISION_MODELS.md).

### Added

- **Smart GPU auto-placer (`auto_place`).** Opt-in per manifest (default `false` — existing behavior is unchanged). When enabled, the manager picks the GPU for a co-resident model at spawn time by choosing the card with the most suitable free VRAM, rather than always honoring the manifest's pinned default. Each card keeps its own safety floor free, and a spawn is refused rather than blindly admitted when no card can hold the model. Documented in [docs/MULTI_GPU_PLACEMENT.md](docs/MULTI_GPU_PLACEMENT.md).
- **Per-card VRAM accounting for multi-model co-residence.** VRAM headroom is now tracked per GPU rather than in aggregate, so two models sharing a host are each costed against the card they will actually land on. Aggregate accounting could previously see "enough free VRAM" across the host while the specific target card had none.
- **Content-addressed vision-projector support (`mmproj_blob_sha256`).** An optional manifest field naming the projector as a blob checksum in the content-addressed store; the manager resolves it and injects the projector at spawn. The raw path-bearing projector flag remains in the denied set, so a manifest still cannot smuggle an arbitrary host path into the engine command line. Documented in [docs/VISION_MODELS.md](docs/VISION_MODELS.md).

- **Hybrid `qwen35` model support.** A `qwen35` model is a hybrid — a mix of state-space (SSM) and attention layers. It serves in every existing residency mode: single, series-parallel (`--parallel N`), and double-parallel (several models resident at once).
- **New manifest fields `arch` and `hybrid_kv_ratio` for hybrid models.** `arch` (string, default `""`) names the model architecture — set `arch: "qwen35"` for a state-space/attention hybrid; this is load-bearing (it triggers the dimension-aware KV-fit path below). `hybrid_kv_ratio` (float, `0.0`–`1.0`, default `1.0`) is the fraction of layers that contribute a growing per-token KV cache; it scales the KV term on the **file-size fallback** estimate path only (see the dimension-aware bullet below). The default of `1.0` means pure attention — byte-identical behavior for every existing model.
- **New manifest field `kv_bytes_per_token` — an operator-measured KV-fit override.** Optional (`float | None`, default `None`). When set it is the model's **measured effective KV cache cost in BYTES per token** (e.g. from an `nvidia-smi` reading) and is used **verbatim** by the KV-fit estimate — no quant-scale, no `hybrid_kv_ratio` multiply. It carries a **1 KiB/token floor** (`Field(ge=1024.0)`) so a KiB-vs-bytes typo (e.g. `13.5`) is rejected at manifest-load rather than silently under-counting. Default `None` disables it — byte-identical for every existing model.
- **Dimension-aware KV-fit estimate for hybrid / low-bit models.** For a `qwen35` model the manager parses the real GGUF attention dims (via the new `src/turbohaul/_gguf_meta.py` KV-header reader) and sizes the KV cache from them. The estimate follows a strict precedence: **measured `kv_bytes_per_token` override → parsed GGUF attention dims → legacy file-size heuristic.** The first two paths deliberately **ignore `hybrid_kv_ratio`** (the attention-layer count already reflects the hybrid fraction, so re-applying the ratio would under-count). Any non-`qwen35` model — or one whose GGUF can't be parsed and has no override — uses the legacy file-size heuristic unchanged (byte-identical). This closes an under-count where an ultra-low-bit model's small file size made the heuristic badly under-estimate its KV cache.
- **New GGUF metadata reader `src/turbohaul/_gguf_meta.py`.** A small, stdlib-only, read-only parser of the GGUF key/value header (never tensor data) that extracts a model's attention dims for the dimension-aware KV-fit estimate. It never raises to its caller — any malformed/missing input returns `None` and falls back to the legacy path.

### Changed

- **KV-fit and VRAM estimates are now dimension-aware for hybrids, with `hybrid_kv_ratio` as the file-size fallback.** For a `qwen35` model the estimate is derived from the real GGUF attention dims (or an explicit measured `kv_bytes_per_token`); `hybrid_kv_ratio` now scales **only** the legacy file-size fallback path — the one used when the GGUF dims can't be parsed and no override is set. A model without any of these fields (the defaults) is estimated exactly as before.

### Fixed

- **Pre-fill meter reported a misleading percentage.** The dashboard's pre-fill bar derived its percentage from a denominator that did not match the context actually being admitted, so the bar could sit pegged near the top while the token count kept climbing. It now uses the backend-reported pre-fill percentage, falling back to the admitted context length, and finally to the largest prompt seen. A run with no usable denominator shows a bounded indeterminate state instead of a misleading full bar.
- **Duplicate tracking of the largest observed prompt** in the live monitor, which could report the wrong denominator for the pre-fill meter.
- **Cosmetic defects in source comments and one log line.** A log message read `"the classifier classifier decision"`, and several comments contained a doubled word. These were text-only and affected no behavior.

### Compatibility

- **No new server flags.** The engine detects a model's weight quant automatically from the GGUF header (`general.file_type`), so nothing is added to the safe server-flag allowlist; existing manifests and spawn recipes are unaffected, and no manifest or flag change is required to serve a hybrid model.
- **No new KV-cache type.** Hybrid models reuse the existing turbo KV-cache types — the KV cache path is unchanged.
- **Every new manifest field is optional and defaults to previous behavior.** `arch` (`""`), `hybrid_kv_ratio` (`1.0`), `kv_bytes_per_token` (unset), `auto_place` (`false`) and `mmproj_blob_sha256` (unset) all leave an existing manifest estimated, placed and spawned exactly as before. No migration is required.

## [v0.6.0] - 2026-07-10

_Covers changes since the v0.5.0-public baseline (2026-06-28). Versions v0.3.x–v0.5.x were internal iterations consolidated into that baseline._

### Highlights

- **Multi-agent sessions are now first-class — one GPU, many agents, zero context bleed.** Every sub-agent a client spawns gets its own distinct session ID, so its KV cache lives in an isolated bin that no other agent — sibling sub-agent, curator, or the main agent — can read, overwrite, or muddy. Previously, concurrent agents sharing a single GPU could easily cross-contaminate each other's context; keying every bin to the agent's identity makes that structurally impossible. See [docs/MULTI_AGENT_SHARING.md](docs/MULTI_AGENT_SHARING.md).

- **Precomputed KV cache makes returning to a long context nearly free.** The main agent keeps its context warm in VRAM between tool calls and restores its full precomputed prefix when it comes back from a batch of sub-agent work — instead of re-reading the whole conversation from scratch. Measured in validation: 96% of a ~105,000-token context was reused as a common prefix, and a 154,647-token context was restored with just a 29-token prefill — 629× less prefill work than recomputing it. Sub-agents and the curator get the same warm reuse while they run.

- **KV cache now survives a model swap.** When the engine has to unload one model to load another, Turbohaul saves the returning session's slot state to disk and restores it on the way back, so swapping models no longer forces an expensive re-prefill of everything that was already computed. Works whether the box is juggling several models or running just one. (#79, #82)

- **Disposable roles clean up after themselves.** Sub-agents, the curator, and compression passes are transient by design, so when one finishes its job its KV is thrown away by contract — enforced both on each turn and again when the model unloads — and can never survive to pollute later work. The main agent always keeps its cache; the throwaway roles never do.

- **A model-swap-safe storage tier keeps caches around only as long as they're useful.** Returning sessions restore instantly from system RAM (a tmpfs tier), and their caches are copied down to SSD so they outlive a full unload. Automatic cleanup keeps both tiers bounded — caches older than 6 hours are dropped, the SSD tier is capped at 40 GiB and the RAM tier at 20 GiB, and a mid-copy cache is never deleted out from under itself. An opt-in purge (off by default) can also drop any cache built for a different engine or model.

- **The role of every request is now declared explicitly, and the dashboard shows the truth.** A client labels each request as the main agent, a sub-agent, the curator, or a compression pass, and those labels drive every save/restore decision — so a curator turn, for example, can ride the main agent's context read-only but can never overwrite it. An unlabeled request falls back to the old behavior, byte-for-byte, so existing callers are unaffected. The dashboard was rebuilt to match: it now shows a live prefill-progress bar, whether a model is genuinely busy versus idle, an accurate grace-timer, and a per-model indicator confirming the model is resident and its cache was restored.

- **Engine hardening — the KV-save path no longer takes the whole engine down with it.** Earlier builds could poison a saved cache with mid-operation engine state and then crash silently on the next restore, because the engine's abort output was being discarded. This release vendors the engine so its exact build is pinned and reproducible, captures that abort output instead of throwing it away, automatically quarantines any cache bin implicated in three strikes (preserving it as evidence), detects and recovers a dead engine instead of hanging on it, and surfaces a clear "engine stalled" state on the dashboard. The net effect: the crash-and-hang loops previously seen during multi-agent bursts no longer occur.

- **Everything ships in one repository — clone it and run, fully offline.** The whole system is now self-contained in a single repo: the inference engine's source, the Python dependencies as wheels, the frontend (source plus a prebuilt bundle), and a ready-to-run prebuilt image. There's no external registry, package index, or second repository to fetch — clone the repo and either run the prebuilt image or build from source with the network switched off. All vendored dependencies are permissively licensed and their licenses are recorded in-repo. See the README's *Offline use* section.

### Added

- Per-agent, single-copy KV caching — each session-and-role pair gets its own cache bin, fingerprinted so sub-agent and curator bins never collide.
- Two-tier cache storage — a fast RAM tier for instant restore plus an SSD tier that survives a full model unload, with caches copied down atomically.
- Automatic cache cleanup — drops caches past a 6-hour age, caps the SSD tier at 40 GiB and the RAM tier at 20 GiB, keeps at most 100 RAM-tier files, and never deletes a cache younger than 60 seconds (to avoid racing an in-flight copy). An opt-in purge (off by default) removes caches built for a mismatched engine or model.
- Per-request control over whether a throwaway role saves its cache, set by the calling client with no environment variables needed.
- A per-model status indicator on the dashboard confirming the model is resident and its cache was restored.
- Dead-engine recovery — a proactive liveness sweep plus a check on the serving path so the manager re-spawns a silently-dead engine instead of hanging on it.
- The engine sidecar's output is now captured to a file rather than discarded, so a crash leaves a diagnosable trace.
- Three-strikes cache quarantine — a bin implicated in repeated failures is moved aside automatically and preserved as evidence.
- Seam-integrity repair — on returning from a sub-agent wave the manager rebuilds the main agent's cache tip cleanly, ending the abort chain that used to crash the wave return.
- Honest dashboard telemetry — the grace clock only appears when the model is actually idle, a prefill pill and progress bar reflect real work, a "busy" state shows while the model is serving, and a red "no telemetry" warning appears after 120 seconds of silence.
- A settings control for the SSD cache ceiling, with live usage and headroom shown in the UI.
- Reasoning blocks are now preserved on tool-call turns, fixing a context divergence that used to appear partway through long sessions.
- Live-output pane now auto-follows new tokens only while you're scrolled to the bottom — scroll up to read and it stops yanking you back down.
- An idempotent completion cache with single-flight de-duplication, so a retried request can't double-run.
- KV reuse now works when the box serves several models or several context windows at once — every save/restore decision routes through one unified policy, and a multi-model path that previously never restored its cache now does.
- Fully self-contained, offline build — the engine source, Python wheels, and frontend (with a committed build) are all vendored in-repo, and `Dockerfile.engine-src` builds the entire stack with no PyPI, npm, or external git access.

### Fixed

- **Incoming requests lost their role labels.** When a warm, idle model inherited a new request, it was overwriting that request's fresh role labels with the previous occupant's cached ones — so a sub-agent could be misfiled as the main agent. The new request's labels now always win.
- **Silent crash loops on wave return.** Caches saved mid-turn captured transient post-curator engine state and were wrongly marked clean; restoring one aborted the engine, and six crash cycles died invisibly because the engine's abort output was being discarded. Fixed by saving only at the clean unload seam and by capturing that output.
- **Manager hung on a dead engine.** When the idle model's engine died silently, the manager kept reusing the dead process for 10+ minutes instead of re-spawning it. It now detects the dead engine and recovers.
- **Restoring from SSD clobbered the fresh cache.** A size-mismatch "repair" step overwrote the current turn's cache with a stale pre-compression copy on every scan, pinning reuse at the stale version. The repair now only fills in a missing copy and never overwrites a live one.
- **Reasoning blocks vanished on tool-call turns.** A position-based strip was deleting reasoning from every saved cache on tool-call turns, so a later resend diverged from what was originally saved. Reasoning is now preserved.
- **Stall alarm fired on healthy work, and real stalls read as normal.** The token counter used to classify progress kept climbing through normal decoding, so a genuine stall was labelled "prefill" forever while healthy decoding painted a stuck "prefill 1%". The classifier now reads the counter that actually freezes on a stall.
- **The SSD cache-cap setting was a silent no-op.** The ceiling was read from the environment but never wired to the running config, so raising it did nothing. It's now applied at runtime and editable from the Settings tab.
- **Unknown model tags now return 404** on the chat endpoints instead of failing obscurely.
- **Oversized request bodies are now rejected with 413** at the middleware layer.
- **Fixed a delete-then-use race in manifest handling.**
- **Blocking file I/O moved off the event loop** so a slow disk no longer stalls request handling.
- **VRAM admission now counts both halves of the KV cache** (value cache as well as key cache), so the box no longer over-commits memory.
- **Guarded an empty-choices response** that could crash the caller.
- **Tool-call messages with `null` content no longer crash the chat endpoints.** Standard OpenAI-format clients that send a tool-call turn with `content: null` used to hit a server error; the content is now handled cleanly on both the streaming and non-streaming paths.

### Changed

- **The main agent's cache is now written only when the model unloads, not on every turn.** Per-turn work just keeps the live cache warm in VRAM; the single disk write happens once, cleanly, at unload. This is what ended the mid-turn poisoned-save crashes.
- **Warm restores now force a clean reload by default**, eliminating the residual "no cache data" errors that used to surface on reuse.
- **A tail-integrity check refuses to save** a cache whose reasoning primer wasn't properly stripped, preventing a known corruption from reaching disk.
- **KV save timeout raised from 10s to 120s.** A chronic timeout was freezing the cache at ~25 turns; save failures are now logged with enough detail to diagnose.
- **The curator can now ride the main agent's context read-only** when that route is enabled (off by default), guaranteed never to overwrite the main agent's saved cache.
- **Caches are only saved for single-series, large-enough contexts** — a multi-series slot won't save, and a context has to clear a minimum size before it's worth caching.
- **Garbage collection now piggybacks on the existing idle sweep**, throttled to run at most every 5 minutes.
- **The mismatched-engine purge is opt-in and off by default**; when enabled it drops caches whose build/model/context fingerprint doesn't match the running engine, and never touches the live idle model's cache.
- **Model scheduling no longer thrashes between same-model turns.** When several sub-agents on the same model were queued behind one request for a different model, the scheduler used to swap the model out and back in unnecessarily. It now drains queued same-model work first (still swapping promptly if a waiting request would otherwise starve), and briefly holds a model warm for a same-model request already in the queue.

### Known issues / limitations

- **The cache-restore verifier is observability-only for now.** The cold-spawn path doesn't yet carry expected token counts, so the per-model indicator confirms a restore was attempted and the slot is live but can't check restore depth against an expectation — it may report a restore as unverified even when reuse is actually working. The engine log and wave-return counters remain the authoritative reuse signals; real expected-versus-actual verification is a planned follow-up.
- **Some engine-side crash classes are mitigated in the manager, not root-fixed.** The strict-extension abort on hybrid-recurrent models and rare cache-save truncation are handled by rebuilding the cache and quarantining bad bins, but the underlying fixes belong in the vendored llama.cpp fork and remain open upstream.
- **The `monitor` config setting requires a restart** — it's part of runtime config but can't be changed live and isn't returned by the config read endpoint.
- **Most cache-tuning knobs are environment-only.** Only the SSD cache ceiling is adjustable from the Settings tab; the RAM ceiling, cleanup age and count thresholds, sweep interval, and purge settings all require environment variables.
- **Auxiliary background tasks are unlabeled for now.** Some calls an agent's harness makes on its own behind the scenes — title generation, session search, skill lookups, vision, web extraction, and approval checks — currently arrive without a role tag or session identity. They work correctly, but because they're unlabeled they can't ride the main agent's warm cache and instead take the slower full-prefill path. Threading the agent's session context through these auxiliary calls so they can reuse cache is a planned follow-up.
- **Not in this release:** further KV-cache work is still in review — request classification, a fuller completion cache, fingerprint-keyed saves, byte-match self-check, identity shadowing, stale-anchor age reclaim, and shadow re-prefill saves — targeted for a future release.

### Known issues / limitations

- `jinja: true` in the model's manifest is still required for any tool-call work. Tool-call recovery (above) catches the case where a jinja template emits calls as text-JSON; it does not synthesize calls when the model never emits anything tool-call-shaped.
- Multi-residency (two models in VRAM simultaneously) is not supported in v0.2.x. Single-slot serialization is the v0.2 invariant; multi-residency is a v0.3 roadmap item.
- `--reload` uvicorn mode is banned in production. Production uses `docker restart <container>` for code changes.
- `image-vs-patches` debt: prior v0.2.x runtime updates were applied as `docker cp` overlays on the running container rather than baked into a new image. v0.2.3 closes this via the `v0.2.3-cuda-bindmount` commit. Going forward, any non-trivial production deploy MUST `docker commit` + re-save tarball + update auto-recovery references, OR rebuild from `Dockerfile.cuda-multi` against your current source tree.

### Upgrade path

```bash
# Build the image from source (see the README build instructions)
docker build -f Dockerfile.cuda-multi -t turbohaul-manager:v0.2.3 .

# Stop + remove the old container (state survives because of the bind-mount)
docker stop turbohaul-manager
docker rm turbohaul-manager

# Run the new container with the canonical bind-mount layout
docker run -d --name turbohaul-manager     --restart unless-stopped     --runtime nvidia --gpus all     -p 11401:11401     -p 11434:11434     -v /var/lib/turbohaul:/var/lib/turbohaul     -e TURBOHAUL_IDLE_HOT_SECONDS=600     -e TURBOHAUL_GRACE_SECONDS=30     turbohaul-manager:v0.2.3
```

Existing state (`state.sqlite`, `manifests/*.yaml`, `blobs/sha256/*`) is preserved through the bind-mount. First request to a new model may cold-load 30 to 60 seconds; subsequent same-thread follow-ups within the grace + IDLE_HOT windows reuse the warm slot.
